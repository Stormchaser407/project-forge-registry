## Mission

This ledger prevents GitHub repository identity from depending on memory, chat history, or visual clutter. Every materially reviewed repository receives an explicit lifecycle and disposition under the Project Forge Repository Lifecycle and Compliance Standard.

This is a preservation-first cleanup. Repository deletion is not part of this transaction. Archival or supersession requires preservation evidence and a named replacement or reason where applicable.

## Lifecycle vocabulary

Use the Forge standard lifecycle values: `active`, `maintenance`, `waiting`, `incubator`, `dormant`, `reference`, `superseded`, `completed`, and `archived`.

Additional disposition language in this ledger:

- **retain** — keep visible and available in its current role;
- **harvest** — inspect and preserve useful unique assets in the named canonical system before archival;
- **archive-ready** — preservation decision is complete enough for GitHub archival once any listed final manual step is performed;
- **cold-store** — future fleet-side recommendation for a verified local repository that should leave normal working surfaces without losing history;
- **promote** — future fleet-side recommendation for unique local work lacking a durable canonical remote.

## Future fleet reconciliation direction

GitHub is only one estate surface. Forge should later evolve through these gates:

1. **Remote Estate Census** — GitHub repos, owners, lifecycle, canonical relationships, deployment/public authority.
2. **Fleet Repository Census** — read-only discovery of Git roots across authorized hosts and mounted project roots; identify remotes, branches, HEADs, worktrees, dirty state, untracked files, size, and host/path.
3. **Reconciliation Engine** — match local repositories to GitHub and one another using Git identity/history rather than filenames; detect unique/unpushed commits and divergent histories.
4. **Lifecycle Advisor** — recommend `promote`, `sync`, `reconcile`, `supersede`, `archive`, `cold-store`, `quarantine`, or `delete-local-copy-after-proof`.
5. **Guarded Actions** — only after explicit authorization, perform bounded remote promotion, archival preparation, bundle/cold-storage creation, or local cleanup with proof that no unique commits or untracked material will be lost.

Deletion must never be recommended solely because two paths or filenames look similar. A destructive recommendation requires evidence that all reachable commits and meaningful uncommitted/untracked material are preserved in an approved canonical destination.
